# 2026-10-08 抖音授权服务恢复记录

故障表现：手机登录或任务授权请求失败；9000 总后台 `/health` 正常，但 `/douyin/health` 返回 Nginx 502。

现场原因：`douyin_admin-api-1` 容器不存在，抖音 API 镜像也不在本机，`127.0.0.1:18081` 无监听。现有 API 源码、Compose 配置、环境配置和绑定挂载的数据库仍保留。没有足够日志判断容器和镜像为何消失，不将原因归结为用户密码或账号授权。

在 `/opt/douyin_admin` 执行以下恢复命令，仅启动 api 服务：

```sh
docker compose up -d --build --no-deps api
```

恢复使用现有数据库 `/opt/douyin_admin/data/app.db`；没有修改账户权限或密码，没有重启总后台、Nginx、Docker 守护进程或其他容器。API 已配置 `restart: unless-stopped`；该策略可以处理进程退出和宿主机重启，但不能恢复已被删除的容器或镜像。

验证结果：

- 18081 API 健康检查和 9000 `/douyin/health` 均返回 HTTP 200。
- 用户提供的手机号存在、处于 active 状态、未设置到期时间；提供的密码与当前服务端密码哈希匹配。
- 使用唯一临时设备标识请求真实登录接口，HTTP 200；收到令牌后请求设备心跳，HTTP 200、status=active。
- 错误令牌被 HTTP 401 拒绝。
- 临时设备和对应测试登录审计已删除；现有 15 台设备的账号归属、状态和令牌哈希与测试前一致。
- 用户/设备/审计记录数量分别仍为 12 / 15 / 52。测试登录更新了该账号的最近登录时间。
- 测试前通过 SQLite 在线备份保存数据库：`/opt/518-deploy-backups/douyin-recovery-20261008-070047/app.db`。
- 总后台 `/health` 返回 HTTP 200；总后台进程 PID 1468、Nginx PID 22722–22726 与恢复前观察一致，未重启；其他运行容器仍在运行。
- 服务器本机通过 Nginx 访问 9000 正常；但从本工作站访问公网 `47.120.41.123:9000` 超时。服务器 firewalld 和 iptables 已有 9000/tcp 放行规则；与外部探测同步抓包时，服务器网卡未收到对应 SYN，说明该次公网连接未到达主机，可能受云平台安全组或中间网络路径影响。没有为验证而新增或放宽公网规则。
- 复核时使用服务器当前 SSH 密码通过系统 SSH 客户端成功登录；在服务器本机用手机号和密码请求 `/douyin/api/v1/auth/login` 返回 HTTP 200、`status=active`。测试生成的临时设备记录已删除。

本次不需要更新 APK。服务端内部登录与设备心跳链路已通过测试；客户真实手机尚未完成端到端登录验证。若客户仍无法连接，应先在云平台检查该服务器安全组/公网 ACL 是否允许客户端来源访问 TCP 9000，并核实手机实际使用的服务地址。
